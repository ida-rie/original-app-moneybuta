# 認可回帰チェックリスト

このドキュメントは、認証・認可まわりの修正後に
「誰がどの API を叩けるべきか」を確認するための最小チェックリストです。

## 前提

- 親アカウントAと、その子アカウントA1が存在する
- 親アカウントBと、その子アカウントB1が存在する
- それぞれ別家庭として扱う
- API 確認時は、呼び出し元の `Authorization: Bearer <access_token>` を付与する

## 期待するルール

- 親は自分の子どもの情報だけ参照・更新できる
- 子は自分自身の情報と、自分に紐づくクエストだけ扱える
- 他家庭の子ども情報は参照も更新もできない
- 子アカウント作成は、親としてログイン済みの状態でのみ成功する

## GET 系

### `/api/users/[id]`

- 親Aが親A自身を取得できること
- 親Aが子A1を取得できること
- 親Aが子B1を取得すると `403` になること
- 子A1が自分自身を取得できること
- 子A1が親Aや子B1を取得すると `403` になること
- 未認証で叩くと `401` になること

### `/api/quests?childId=...`

- 親Aが子A1のクエスト一覧を取得できること
- 親Aが子B1のクエスト一覧を取得すると `403` になること
- 子A1が自分のクエスト一覧を取得できること
- 子A1が子B1のクエスト一覧を取得すると `403` になること
- 未認証で叩くと `401` になること

### `/api/base-quests?childId=...`

- 親Aが子A1の基本クエスト一覧を取得できること
- 親Aが子B1の基本クエスト一覧を取得すると `403` になること
- 子A1が自分の基本クエスト一覧を取得できること
- 子A1が子B1の基本クエスト一覧を取得すると `403` になること
- 未認証で叩くと `401` になること

## 作成系

### `POST /api/basic-amount`

- 親Aが子A1に対して基本金額を作成・更新できること
- 親Aが子B1に対して送信すると `403` になること
- 子A1が自分自身を指定して送信すると `403` になること

### `POST /api/base-quests`

- 親Aが子A1に対して基本クエストを作成できること
- 親Aが子B1に対して送信すると `403` になること
- 子A1が自分自身を指定して送信すると `403` になること

### `POST /api/users/signup`

- 親アカウント新規登録は未認証でも成功すること
- 親Aとしてログイン中なら、`role=child` かつ `parentId=親A` で成功すること
- 親Aとしてログイン中に `parentId=親B` を送ると `403` になること
- 子A1としてログイン中に `role=child` を送ると `403` になること
- 未認証で `role=child` を送ると `401` になること

## 更新・削除系

### `PUT/DELETE /api/basic-amount/[id]`

- 親Aが自分の子A1に紐づく基本金額を更新・削除できること
- 親Bや子A1が同じレコードを更新・削除すると `403` になること

### `PUT/DELETE /api/base-quests/[id]`

- 親Aが自分の子A1に紐づく基本クエストを更新・削除できること
- 親Bや子A1が同じレコードを更新・削除すると `403` になること

### `PUT /api/quests/[id]/complete`

- 子A1が自分のクエストを完了できること
- 親Aや子B1が同じクエストを完了しようとすると `403` になること

### `PUT /api/quests/[id]/approve`

- 親Aが子A1のクエストを承認できること
- 子A1や親Bが同じクエストを承認しようとすると `403` になること

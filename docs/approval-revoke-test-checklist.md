# 承認解除機能 テストチェックシート

このチェックシートは、クエスト承認解除（`DELETE /api/quests/[id]/approve`）の導入後に、
既存機能へ影響が出ていないことを確認するための実施用ドキュメントです。

## 前提データ

- 親A / 子A1（同一家庭）
- 親B / 子B1（別家庭）
- 当日分クエスト `Q_TODAY`（子A1に紐づく）
- 前日分クエスト `Q_YESTERDAY`（子A1に紐づく）

## 実施ルール

- APIは必ず `Authorization: Bearer <access_token>` 付きで実行する
- 期待ステータスとレスポンスメッセージを確認する
- UI確認時は、親Aで子A1を選択して操作する

## 1. 完了/完了解除 回帰

1. 子A1で `Q_TODAY` を完了する
- 期待: `PUT /api/quests/[id]/complete` が `200`
- 期待: 一覧で `completed=true`

2. 子A1で `Q_TODAY` の完了を取り消す
- 期待: `DELETE /api/quests/[id]/complete` が `200`
- 期待: 一覧で `completed=false`

3. 同じクエストを再度取り消す
- 期待: `DELETE /api/quests/[id]/complete` が `409`

4. 子A1で再度 `Q_TODAY` を完了する
- 期待: `PUT /api/quests/[id]/complete` が `200`

5. 親Aで同じ `Q_TODAY` を承認する
- 期待: `PUT /api/quests/[id]/approve` が `200`
- 期待: 一覧で `approved=true`

6. 同じクエストを再完了する
- 期待: `PUT /api/quests/[id]/complete` が `409`

7. 子A1が承認済みクエストを取り消す
- 期待: `DELETE /api/quests/[id]/complete` が `409`

8. 同じクエストを再承認する
- 期待: `PUT /api/quests/[id]/approve` が `409`

## 2. 承認解除（正常系）

1. 親Aが当日承認済み `Q_TODAY` を解除
- 期待: `DELETE /api/quests/[id]/approve` が `200`
- 期待: `approved=false`, `approvedAt=null`, `approvedBy=null`
- 期待: UIが「承認」ボタンに戻る

2. 親Aが同クエストを再承認
- 期待: `PUT /api/quests/[id]/approve` が `200`

## 3. 承認解除（異常系）

1. 未承認クエストを解除
- 手順: 承認前の `Q_TODAY` に対して `DELETE`
- 期待: `409`

2. 前日以前の承認を解除
- 手順: `Q_YESTERDAY` を前日承認済み状態にして `DELETE`
- 期待: `409`（当日中のみ解除可能）

3. 子A1が解除APIを実行
- 期待: `403`

4. 親Bが子A1のクエスト解除APIを実行
- 期待: `403`

## 4. 既存金額表示への影響

1. 親Aで子A1のホームを表示（当月）
- 期待: 承認済みクエストのみ `rewardSum` に含まれる

2. 当日承認 → 解除 → 再承認の順に操作し、月次グラフを確認
- 期待: 操作結果に応じて当月合計が増減する
- 期待: 解除直後に該当クエストが履歴表示から外れる

3. 他家庭 `childId` で `GET /api/amount/monthly` を実行（親Aで子B1指定）
- 期待: `403`

## 5. UI回帰

1. 親画面
- 未完了: 「未完了」
- 完了未承認: 「承認」
- 承認済み: 「承認解除」

2. 子画面
- 未完了: 「やったよ」
- 完了未承認: 「やったよを けす」
- 承認済み: 「クリア！」
- 期待: 子画面に承認解除導線は表示されない
- 期待: 親が承認済みの場合、やったよ取り消しはできない

## 6. 競合・多重操作

1. 同一クエストを2端末で同時承認
- 期待: 片方 `200`, もう片方 `409`

2. 同一クエストを2端末で同時解除
- 期待: 片方 `200`, もう片方 `409`

3. 承認と解除をほぼ同時に実行
- 期待: 最終状態がどちらか一方に確定し、失敗側は `409`

4. 同一クエストを2端末で同時に完了解除
- 期待: 片方 `200`, もう片方 `409`

5. 完了と完了解除をほぼ同時に実行
- 期待: 最終状態がどちらか一方に確定し、失敗側は `409`
